## 1. 技术选型

| 维度 | 选型 | 选型理由 |
|------|------|---------|
| 前端框架 | Vue 3（Composition API + `<script setup>`） | 渐进式、响应式高效、生态成熟 |
| 语言 | TypeScript | 类型安全，题目联合类型可被静态校验 |
| 构建工具 | Vite | 冷启动快、按需编译、内置 TS/JSON 支持 |
| 数据 | 打包 JSON（`src/data/questions.json`） | 题库固定、加载即时，契合纯前端定位 |
| 本地存储 | localStorage | 进度/错题持久化，无需后端 |
| 测试 | Vitest + @vue/test-utils + happy-dom | 与 Vite 同源、配置零成本，覆盖单元 + 组件 |
| 数据生成 | Node 脚本（jszip 解析 docx） | 题库一键重建，数据可追踪 |

## 2. 总体架构

```
┌──────────────────────────────────────────────┐
│                  浏览器 (Vue 3 SPA)            │
│                                              │
│  App.vue ── 筛选 / 导航 / 统计 / 错题本        │
│    └── QuestionCard.vue ── 渲染 + 即时判分     │
│                                              │
│   lib/questions.ts ── 筛选 / 判分 / 工具       │
│   lib/progress.ts  ── localStorage 存取       │
│   data/questions.json ── 题库数据源           │
└──────────────────────────────────────────────┘
        ▲ 生成一次（脚本）
  scripts/build-questions.mjs ── 解析 docx
```

- **单向数据流**：题库 JSON 为唯一数据源；作答结果写入进度存储，各视图按需派生。
- **数据与逻辑分层**：纯函数逻辑（判分/筛选/进度）抽到 `lib/`，组件只负责展示与交互，便于测试。

## 4. 数据模型

### 4.1 题型联合类型（`types.ts`）

```ts
type QuestionType = 'single' | 'blank' | 'judge'

interface BaseQuestion {
  id: number
  type: QuestionType
  chapter: string   // 归一化章节名
  question: string
}

interface SingleQuestion extends BaseQuestion {
  type: 'single'
  options: string[] // A-D 选项
  answer: number    // 正确答案下标
}

interface BlankQuestion extends BaseQuestion {
  type: 'blank'
  answer: string    // 标准答案
}

interface JudgeQuestion extends BaseQuestion {
  type: 'judge'
  answer: boolean   // 对(true)/错(false)
}

type Question = SingleQuestion | BlankQuestion | JudgeQuestion
```

> 采用**可辨识联合**，统一 `question` 字段、按 `type` 精确收窄，保证类型安全。

### 4.2 进度存储（`progress.ts`）

- 键：`web-review-progress-v1`
- 值：`Record<questionId, boolean>`（`false` 即错题）

```ts
type ProgressRecord = Record<number, boolean> // id -> 是否答对
```

- 作答即增量更新并覆盖；`wrongIds()` 派生错题集合。
- 通过 `hasStorage()` 兼容无浏览器环境的场景（测试/SSR），回退内存对象。

## 5. 题库数据生成

`scripts/build-questions.mjs`

1. 用 `jszip` 读取 `*.docx` 内 `word/document.xml`，剥离 XML 标签 → 纯文本行。
2. 按三种分节头识别题型（`单选题库` / `填空题库` / `判断题库`）。
2. 逐行解析生成题目，**章节名归一化**（如 `SpringBoot`、`MyBatis 与 Druid`、`JSON 与 JWT`、`Vue3 基础` 等跨题型统一）。
3. 标注自增 `id`，写入 `src/data/questions.json`。

```bash
npm run build:data   # node scripts/build-questions.mjs
```

> 题库源更新后重跑脚本即可增量替换数据，无需改动业务代码。

## 6. 核心流程

### 6.1 筛选 → 练习

```
选择题型(all/单选/填空/判断) + 章节(all/8 章节)
        │
        ▼
filterQuestions(bank, types, chapters)  → 题目池 basePool
        │
        ▼
当前题目索引 currentIndex ←→ QuestionCard 渲染
```

- 结果由 `basePool` 计算属性派生，筛选变化自动重置回第 1 题。

### 6.2 即时判分（`lib/questions.ts`）

```ts
function checkAnswer(q: Question, input): boolean {
  switch (q.type) {
    case 'single': return q.answer === input          // 下标比对
    case 'judge':  return q.answer === input          // 布尔比对
    case 'blank':  return normalizeText(q.answer)     // trim + 压缩空白 + 忽略大小写
                     === normalizeText(String(input))
  }
}
```

- 单选 / 判断：点击即判分并高亮正确项，作答后锁定。
- 填空：输入后点“核对”判分，展示标准答案。

### 6.3 进度与错题本

```
作答 emit(submit) → saveAnswer(id, correct) → progress 更新（持久化）
                                                  │
                                                    ▼
wrongIds() 派生错题 → 错题本模式渲染，答对后自动移出
```

## 9. 后续演进方向（技术侧）

- **随机 / 乱序**：抽取池中随机打乱，需在 `filterQuestions` 层增加 `shuffle` 选项。
- **模拟考试**：节点抽取 + 计时器 + 交卷汇总，进度模型扩展为会话级 `Record`。
- **薄弱点分析**：在 `ProgressRecord` 基础上按 `chapter/type` 聚合正确率。
- **多题库切换**：`questions.json` 扩展为题库清单 + 当前激活题库选择。
- **若题库动态化**：引入后端 API / 前端读取单题数据，前端解析层保持不变。
